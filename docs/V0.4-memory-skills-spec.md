# Spec: 0.4.0 受控记忆体与客服技能中心

## Assumptions

1. “学习”是从运行结果生成经验候选，经人工审核后再进入长期记忆，不是让模型自动改写自己。
2. 不长期保存客户聊天正文、手机号、地址、订单号、截图或完整模型回复；经验候选只保存抽象意图、依据 ID、风险和处理结果。
3. 长期记忆属于经验和流程提示，不能替代库存、价格、尺码、物流等实时事实。
4. 技能是纯文本、可审计的流程说明；本版本不允许技能携带或执行脚本、命令、联网工具或外部写操作。
5. GitHub 技能仅作为公开研究和来源标注，转换为适合本软件安全边界的本地技能，不直接执行仓库内容。

## Objective

为售前智服增加可持续积累但可控的记忆闭环，以及可安装、启停、编辑、删除、导入导出的技能中心。Qwen 在每次决策时只加载与当前问题相关的已审核长期记忆和已启用技能；候选记忆、停用技能和未知来源内容不能影响回复。

## Research Basis

- 采用 Agent Skills 的轻量结构：名称、描述和完整指令是技能最小核心。
- 参考 `composio-community/support-skills` 中无需外部工具的客服思路：情绪与紧急度、语气优化、愤怒客户降级、回复质检、回复模板。
- 删除所有 Bash、Composio、Gorgias、CRM、邮件发送等外部执行步骤，保留纯推理流程并加上现有代码安全门。

## Tech Stack

## Project Structure

- `AgentDesk.Core`：记忆/技能领域模型、检索与经验记录契约
- `AgentDesk.Infrastructure`：本地原子存储、审核、启停、导入导出、指纹和经验抽象
- `AgentDesk.AI`：相关记忆/技能加载、`skillsUsed` 契约和事实隔离校验
- `AgentDesk.App`：记忆候选审核、长期记忆管理、技能中心
- `tests`：隐私、审核门禁、检索、技能启停、模型上下文和指纹测试

## Code Style

```csharp
public sealed record ExperienceMemory(
    string Id,
    string Title,
    string Content,
    MemoryReviewStatus ReviewStatus,
    bool IsEnabled,
    int EvidenceCount,
    DateTimeOffset UpdatedAt);
```

- 领域记录不可变，UI 编辑器使用可观察对象。
- 所有文件采用临时文件写入后原子替换。
- 指令内容视为不可信数据，不能覆盖系统规则或成为商品事实。

## Memory Lifecycle

1. **短期上下文**：仅存在于当前 Qwen 请求，不另存聊天全文。
2. **经验候选**：真实影子观察、转人工或自动发送结束后，由代码生成脱敏摘要；模拟账号不记录。
3. **人工审核**：客服主管可编辑候选，确认适用账号、商品和标签后批准。
4. **长期记忆**：只有 `Approved && Enabled` 的记忆可检索；使用次数单独统计，不改变安全指纹。
5. **撤销**：长期记忆修改、停用、删除会撤销正式模式批准；新增候选不会。

## Skill Lifecycle

- 技能字段：名称、描述、分类、触发词、指令、来源、许可证、是否总是应用、审核与启用状态。
- 初始内置技能：回复安全质检、简洁友好语气、情绪与紧急度识别、愤怒客户降级、缺失信息追问。
- 技能按描述和触发词匹配，每次最多加载 4 个；总是应用的技能优先。
- Qwen 输出 `skillsUsed`，只能引用本次提供的技能 ID；未知技能 ID 被拒绝。
- 技能不得执行命令或绕过退款、改价、隐私、尺码等代码安全门。

## Testing Strategy

- 自动经验摘要不包含原始消息、数字串、客户别名或完整回复。
- 候选记忆不能被检索，批准启用后才能进入模型上下文。
- 同类经验合并并增加证据次数，避免候选无限重复。
- 技能启停、编辑、删除、导入导出和恢复内置技能均可验证。
- 低风险回复仍必须有非记忆的事实依据；记忆和技能不能单独放行发送。
- 1280×720 导航与“记忆与技能”页面无裁切，具备空状态和键盘可操作控件。

## Boundaries

- Always：候选先审核；只保存脱敏抽象；变更长期记忆或技能后重跑模拟验收。
- Ask first：联网自动安装新仓库技能、执行技能脚本、同步 CRM/邮件/工单系统。
- Never：自动批准经验；用记忆代替实时商品事实；保存聊天全文；让技能绕过代码安全门。

## Success Criteria

1. 真实处理结果自动形成脱敏经验候选，相同模式可累计证据次数。
2. 候选、已批准、已停用状态清晰；审核后才能影响 Qwen。
3. 技能可新增、编辑、开关、删除、导入导出并恢复推荐内置技能。
4. 至少 5 个经过安全改写的客服技能随软件提供，并标注 GitHub 来源和许可证声明。
5. Qwen 请求包含最多 6 条相关长期记忆和 4 个相关技能，输出记录 `skillsUsed`。
6. 记忆或技能不能充当库存、价格、尺码、物流事实依据。
7. 版本原位升级到 0.4.0，保留既有发布路径、Qwen 密钥和用户数据。

## Open Questions

- 客服平台若未来提供“已解决/满意”信号，可把它作为候选置信度增量；当前版本不假设发送成功等于解决成功。
- 新 GitHub 技能的在线安装保留到后续版本，需增加签名、许可证和指令注入扫描。
