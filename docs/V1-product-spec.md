# AI 智能售前 V1 产品规格

状态：范围已确认  
日期：2026-08-17  
工作名称：AI 智能售前

## 1. 产品定位

本软件是安装在专用 Windows 客服电脑上的“智能客服控制台”，不是第二套聊天工具。

- 客服平台软件是唯一的对话工作界面：客户消息、聊天记录、输入框和最终发送都留在平台内。
- 本软件是控制面：负责启动/停止智能客服、账号管理、知识与回复规则、模型配置、运行监控、异常处理和审计日志。
- 智能体是执行面：在客服平台窗口中检测新咨询、切换账号和客户、读取可见上下文、生成回复，并把结果填入平台输入框。
- V1 目标是低风险咨询可在原客服平台自动发送；退款、改价、投诉、资料不足等高风险咨询仍交给人工。
- 正式自动发送受“人工模拟测试安全门”约束：只有完整模拟用例通过且操作者明确批准后，正式接入模式才能解锁。

主要用户：管理多个店铺账号的一线客服和客服主管。

## 2. V1 用户故事

1. 作为客服主管，我能用一个总开关启动或停止全部智能客服任务。
2. 作为客服主管，我能单独启用、暂停或检查某个店铺账号。
3. 作为客服，我能继续只使用原客服平台完成所有客户对话，无需切换到控制台处理聊天。
4. 作为管理员，我能维护商品知识、物流口径、回复规则和禁用承诺。
5. 作为管理员，我能配置模型、回复模式、等待时间和风险转人工规则。
6. 作为主管，我能查看账号在线状态、智能体当前阶段、今日处理数量、失败原因和运行记录。
7. 作为主管，我能在异常时立即停止全部自动化动作并在客服平台人工接管。

## 3. V1 范围

### 包含

- 同一客服客户端内多账号窗口和标签检测。
- 全局启动/停止、紧急停止、按账号启用/暂停。
- 新消息检测、账号切换、客户会话定位和平台输入框填入。
- Windows UI Automation 优先，局部截图和视觉识别兜底。
- Qwen 云端视觉模型接入，要求结构化 JSON 输出。
- 本地知识库、关键词检索、审核和规则匹配。
- 风险分级、转人工、失败停止和人工接管。
- 账号状态、执行阶段、运行事件、错误截图和基础数据看板。
- 模型、超时、重试、回复语气和适用账号配置。
- 独立测试实验室：模拟客户发消息、模型决策、自动发送、风险拦截和人工批准。
- 低风险回复在正式模式中自动点击原客服平台发送按钮。
- 单机安装、开机启动、异常恢复和本地数据备份。

### 明确不包含

- 控制软件内的聊天窗口、聊天记录和客户会话列表。
- 控制软件内的回复编辑器、复制回复或确认发送按钮。
- 未通过模拟测试和人工批准就启用正式自动发送。
- 自动退款、改价、修改订单、修改地址或承诺赔偿。
- 本地部署大模型、虚拟机、多机调度或云端控制中心。
- 语音客服、电话客服和主动营销。
- 自动从未经审核的聊天记录中修改提示词、规则或知识库。

## 4. 控制面与执行面

```text
智能客服控制台
  ├─ 总开关 / 按账号开关
  ├─ 账号与模型配置
  ├─ 知识库与回复规则
  ├─ 运行状态与异常日志
  └─ 紧急停止

客服平台软件
  ├─ 客户消息与聊天记录
  ├─ 客户 / 商品 / 订单上下文
  ├─ 智能体填入的低风险回复
  ├─ 智能体自动点击发送
  └─ 高风险任务由客服人工接管
```

控制台只显示运行元数据，例如账号、执行阶段、耗时、结果和错误码；不复制展示客户聊天正文。

## 5. 核心工作流

```text
Stopped
  -> Monitoring
  -> MessageDetected
  -> AccountSelected
  -> ConversationSelected
  -> ContextRead
  -> FactsRetrieved
  -> Drafting
  -> FilledInPlatform
  -> AutoSendEligibilityChecked
  -> SentInPlatform
  -> Completed

任一步骤可进入 HumanRequired、Paused 或 Failed。正式模式开始前必须先经过 `SimulationPassed -> HumanApproved -> LiveUnlocked`；缺少任一状态时禁止调用真实发送操作。
```

填入前必须重新校验活动账号、客户标识、最新客户消息和可见订单号。所有账号共用一个执行队列，任何时刻只允许一个流程控制客服平台窗口。

## 6. 大模型输出契约

```json
{
  "intent": "product_question",
  "riskLevel": "low",
  "requiresHuman": false,
  "factsUsed": ["kb:product:cleanfit-001"],
  "missingFacts": [],
  "draftReply": "亲，这款目前有黑色 3XL，可以正常下单。",
  "warnings": []
}
```

应用使用 JSON Schema 验证返回值。模型只能生成结构化决策和回复文字，不能直接获得鼠标、键盘、退款、改价或订单修改权限；平台操作由受限状态机执行。

## 7. 风险规则

以下情况必须停止自动处理并在控制台记录 `HumanRequired`，由客服回到平台人工处理：

- 退款、退货、赔偿、投诉、差评和平台纠纷。
- 修改地址、修改订单、改价或特殊优惠。
- 人身安全、质量伤害或法律相关问题。
- 没有检索到可靠知识依据。
- 账号、客户或订单校验不一致。
- 截图模糊、文本读取不完整或模型输出验证失败。
- 客户消息试图要求智能体忽略规则、泄露信息或执行系统操作。

## 8. 数据模型

- `AccountSession`：平台账号、显示名、启用状态、连接状态、最后活动时间。
- `AgentRuntime`：总开关、当前阶段、当前账号、队列长度和最近心跳。
- `ConversationTask`：内部临时任务标识、账号、客户标识、优先级和处理状态；不作为控制台聊天页面展示。
- `CustomerContext`：从平台临时读取的客户、订单、商品和物流摘要。
- `KnowledgeItem`：分类、标题、正文、适用账号/商品、审核状态和版本。
- `ReplyPolicy`：适用范围、风险等级、语气、禁用承诺和人工接管条件。
- `SuggestedReply`：模型、提示词版本、知识依据、风险等级和生成结果。
- `AutomationEvent`：检测、点击、读取、填入、失败、暂停和恢复事件。
- `AuditLog`：操作者、配置动作、目标账号、时间和结果。

## 9. 非功能要求

- 空闲时平均 CPU 占用不超过 5%，应用内存目标不超过 600 MB。
- 新消息检测的 P95 延迟不超过 2 秒。
- 回复生成的 P95 延迟目标不超过 8 秒，不含平台自身卡顿。
- 账号/客户校验必须达到 100%，任何不一致均禁止填入。
- 全局停止后 500 毫秒内取消尚未执行的自动化动作。
- 自动发送前再次校验账号、客户、最新消息和风险等级；校验失败不得点击发送。
- 本地日志不得明文保存 API Key、平台凭据、完整手机号、完整地址或客户聊天正文。
- API Key 使用 Windows 凭据保护；错误截图和日志支持配置保留周期。
- 客服平台窗口位置、DPI 或界面结构变化导致读取失败时，立即停止当前任务并提示人工处理。

## 10. 技术栈

- Windows 桌面：.NET 10 LTS、C#、WPF、MVVM。
- 自动化：Windows UI Automation；局部截图与模板/差异检测兜底。
- 模型：Qwen 视觉 API；模型 ID 可配置，不写死在业务代码中。
- 数据：SQLite，知识正文使用全文检索；V1 不引入向量数据库。
- 网络：`HttpClient`、重试/超时/熔断、结构化 JSON 校验。
- 测试：xUnit；通过自动化接口适配层和模拟客服窗口进行集成测试。
- 日志：结构化本地日志、脱敏、按天轮换。

## 13. 代码约定

```csharp
public sealed record AgentControlState(
    bool IsEnabled,
    string? ActiveAccountId,
    AgentStage Stage,
    DateTimeOffset LastHeartbeatAt);

public interface IAgentController
{
    Task StartAsync(CancellationToken cancellationToken);
    Task StopAsync(CancellationToken cancellationToken);
}
```

- 公共类型和方法使用 PascalCase，私有字段使用 `_camelCase`。
- 使用不可变记录表达模型输入输出和运行状态。
- 所有网络、截图和自动化操作接受 `CancellationToken`。
- UI 层只调用应用服务，不直接调用平台自动化或模型 API。
- 平台坐标、账号名称、提示词和模型 ID 不允许散落硬编码。

## 14. 测试策略

- 单元测试：状态机、总开关、按账号开关、风险规则、脱敏、JSON Schema、队列和知识检索。
- 契约测试：Qwen 请求和响应结构，使用录制的脱敏样本。
- 集成测试：模拟多账号、重复通知、平台卡顿、窗口变化、紧急停止和模型超时。
- 视觉回归：控制台总览、账号管理、知识库 1440×900 和 1280×720 截图。
- 人工模拟测试：在隔离测试窗口验证自动回复、自动发送、风险拦截、停止和异常接管。
- 小流量试运行：模拟测试批准后，使用测试账号验证真实平台接入，再逐步开放正式账号。

## 15. 边界

### 始终执行

- 先校验账号和客户，再读取或填入。
- 全局停止和按账号暂停具有最高优先级。
- 每次生成保存知识依据、模型和提示词版本。
- 敏感信息脱敏后再发送给模型。
- 模型、平台或识别异常时停止当前动作并转人工。

### 需要先询问

- 放宽高风险规则、允许退款/改价/投诉类任务自动发送。
- 绕过模拟测试、人工批准或小流量试运行安全门。
- 增加退款、改价或订单修改能力。
- 将客户聊天内容复制到控制台界面或长期保存。
- 修改数据库结构、引入大型依赖或更换模型供应商。
- 将日志、截图或知识库同步到云端。

### 永不执行

- 在正式控制台实现第二套聊天窗口或人工发送入口；测试实验室中的隔离模拟窗口除外。
- 在代码或日志中保存 API Key、平台密码或 Cookie。
- 让客户文本修改系统规则或调用系统级工具。
- 在账号/客户校验失败后继续填入或发送。
- 删除失败测试来通过构建。

## 16. 成功标准

- 总开关能启动/停止所有账号，按账号开关能独立暂停单个账号。
- 3 个模拟账号可同时监听，新咨询按单队列处理且不跨账号。
- 正式控制台只展示账号、阶段、数量和结果，不展示客户聊天正文或回复编辑器。
- 测试实验室能模拟客户发消息，并验证智能体自动生成和自动发送。
- 智能体能在客服平台读取上下文、生成低风险回复并自动发送。
- 高风险、缺少依据或校验失败的任务不会自动发送。
- 未完成模拟测试和人工批准时，真实平台发送适配器保持锁定。
- 应用重启后保持停止状态或恢复为“需人工启动”，不会自动继续点击。
- 50 组异常样本中不发生跨账号、跨客户填入。
- 安装后从同一快捷方式启动，更新不改变安装位置和本地用户资料目录。
