# AgentDesk 0.1.1 基线产品审计

审计日期：2026-08-17  
目标版本：0.2.0  
审计方式：在已发布 Windows 原生应用中逐页操作、截图并验证关键阻断路径。

## 结论

现有版本已经形成“模型设置 → 人工模拟 → 窗口校准 → 正式启动”的安全骨架，但还不适合无人值守正式使用。主要原因不是模型能力，而是控制面仍缺少影子观察、流量限制、可恢复的管理操作和足够清楚的上线准备状态。

## 已验证可用

- 未配置 API Key 时，必测套件会阻止继续并跳转到设置页。
- 未填写 API Key 时，连接测试在应用内给出明确错误，不发起无效正式流程。
- 正式发送需模型验证、模拟批准、有效窗口校准三道门禁。
- API Key 使用 Windows 凭据管理器，运行日志不保存聊天正文。

## P0 问题

1. 缺少“仅观察、不发送”的真实平台影子模式，无法在正式自动发送前验证识别准确度。
2. 缺少每日发送上限、每分钟限速和运行中紧急停止入口；模型或界面异常时风险不可控。
3. 校准依赖手填 0–1 坐标，没有截图预览、点击标点和窗口尺寸漂移保护，误配置概率高。
4. 顶部搜索和“同步知识”是无功能控件；导航还会同时显示两个选中项。
5. 知识库缺少搜索、编辑、删除、导入导出和空状态，无法持续维护。
6. 运行记录缺少空状态、结构化字段、筛选、导出和清理确认，无法用于排障。

## P1 问题

- 总览使用静态数字，不能直观看到上线五步是否完成。
- 隐藏页面仍进入自动化树，键盘焦点与读屏顺序可能穿透不可见页面。
- 表单标签没有完整关联到输入控件，状态消息未声明为实时区域。
- 设置页缺少最近验证时间、忙碌状态与预设说明。
- 同平台多账号目前只说明“由视觉识别”，没有可审计的账号标签字段。

## 本版本纳入

- 上线准备清单与可操作的阻断原因。
- 影子观察 / 自动发送双运行模式。
- 每日限额、每分钟限速、连续故障停机和全局停止快捷键。
- 截图预览、点击式输入框/发送按钮标定、尺寸漂移保护和恢复默认。
- 知识搜索、编辑、删除、导入、导出、重复校验和输入限制。
- 结构化日志、筛选、导出、清理确认和保留上限。
- 清理假交互、统一导航状态、空状态和无障碍标签。

## 明确不纳入

- 控制台聊天窗口：与原客服平台重复，会造成上下文分裂。
- Hermes 或多智能体编排：当前瓶颈是安全执行与平台识别，多一层智能体会增加延迟和不可预测性。
- 自动退款、改价、改地址或订单修改：风险过高，继续强制转人工。
- 应用启动后自动开启正式发送：无人确认界面状态时不安全；应用可以启动，但服务始终默认停止。
- 云同步和远程控制：当前为单机方案，会引入新的凭据、隐私和运维面。
