# AI 智能售前实施计划

## 0.5.0 GitHub 自动更新与公开发布（进行中）

1. **可信更新源**：公开 GitHub Release API，只接受 HTTPS 下载地址和指定 Windows 资产。
2. **完整性与解压安全**：SHA-256 必须匹配，拒绝缺失资产和 ZIP 路径穿越。
3. **原位更新**：从临时目录启动新程序作为更新器，等待旧进程退出后覆盖原目录并自动重启。
4. **控制台管理**：在模型设置页展示当前版本、检查状态、Release 说明和下载更新操作。
5. **可复现发布**：本地脚本和 GitHub Actions 统一生成自包含 ZIP、校验文件和 Release。
6. **连续性验证**：保持 `D:\codex项目\ai智能售前\artifacts\AgentDesk-win-x64`、`AI客服.lnk` 和 `%LocalAppData%\AgentDesk` 连续。

检查点：自动化测试通过；本机更新演练通过；公开仓库和 Release 可匿名下载。

## 0.4.0 受控记忆体与技能中心（已完成）

1. **经验闭环**：运行结果生成脱敏候选，同类合并，人工审核后进入长期记忆。
2. **技能治理**：采用 Agent Skills 核心结构，提供可审计的本地技能增删改查、启停和导入导出。
3. **模型接入**：按当前问题加载相关长期记忆和技能，记录 `skillsUsed`，记忆不得替代事实。
4. **安全与隐私**：不保存聊天全文，候选不影响回复，长期变更撤销批准，技能不执行脚本。
5. **原位交付**：完成测试、1280×720 回归并发布到既有应用目录。

## 0.3.0 商品分类与尺码规则（已完成）

1. **规格与安全边界**：商品链接、账号、品类、版型、版本和尺码表独立建模，禁止跨款式猜尺码。
2. **本地规则闭环**：实现审核规则的增删改查、启停、搜索、导入导出、指纹和人工试算。
3. **Qwen 精确引用**：屏幕观察提取商品标识，只把匹配规则注入模型，尺码回复必须引用 `size:` 依据。
4. **发送前复核**：账号、客户、消息之外再复核商品标识，变化即取消真实发送。
5. **原位升级**：完成自动化测试、桌面视觉回归并发布到既有原生应用目录。

## 0.2.0 产品完善（已完成）

1. **基线审计与规格**：完成发布版逐页截图、交互阻断验证、0.2.0 范围与验收标准。
2. **安全运行内核**：增加影子观察、自动发送双模式，日/分钟限额、窗口尺寸保护和停机记录。
3. **管理数据闭环**：补齐知识库增删改查/导入导出、结构化日志筛选/导出/清理。
4. **校准与控制台 UX**：实现截图预览点击标定、上线准备清单、真实指标、统一导航和空状态。
5. **验证与原位发布**：新增自动化测试，Release 零警告，发布到既有目录并用发布版进行桌面实机回归。

本版本不增加控制台聊天窗口、多智能体编排、自动退款/改价、云同步或服务自动启动。

## 里程碑 0：控制台规格与 UI（当前）

依赖：无。

- 固定“控制台不是聊天软件”的产品边界。
- 完成总览、账号管理、知识库与回复规则三张核心界面。
- 控制台只展示运行元数据，不展示客户聊天或回复编辑器。
- 输出脱敏历史咨询样本格式和测试口径。

检查点：用户批准控制面/执行面边界；三张界面通过 1440×900 和 1280×720 视觉检查。

## 里程碑 1：应用骨架与本地数据

依赖：里程碑 0。

- 创建 .NET 10 WPF 解决方案和模块边界。
- 建立配置、日志、凭据保护和 SQLite 迁移机制。
- 实现总开关、按账号开关、运行状态和紧急停止。
- 实现测试实验室和正式模式解锁安全门。
- 建立自动化、模型和知识库的可替换适配层。

检查点：应用可安装、启动、停止和恢复；不接真实平台也能运行模拟账号数据。

## 里程碑 2：平台观察与执行状态机

依赖：里程碑 1。

- 探测客服平台窗口和多账号标签。
- 通过 UI Automation 读取元素；对不可访问区域使用局部截图检测。
- 实现单队列状态机、超时、取消、重试和停止优先级。
- 实现账号/客户二次校验和紧急停止。

检查点：三个账号同时出现通知时仍按顺序处理；全局停止能立即取消后续动作。

## 里程碑 3：上下文读取与知识库

依赖：里程碑 2。

- 在客服平台内读取聊天、客户、商品和订单区域。
- 建立知识录入、审核、停用和全文检索。
- 实现手机号、地址、订单号和账号凭据脱敏。
- 为每次检索生成可审计的知识依据 ID。

检查点：脱敏样本能稳定生成结构化 `ConversationContext`，控制台不显示或长期保存聊天正文。

## 里程碑 4：Qwen 回复决策

依赖：里程碑 3。

- 接入 Qwen 视觉 API。
- 实现提示词版本、JSON Schema、超时、重试和模型切换配置。
- 实现意图、风险、缺失事实、知识依据和建议回复字段。
- 实现提示注入防护和禁止工具权限。

检查点：历史脱敏样本评测达到约定事实正确率和风险转人工率。

## 里程碑 5：模拟自动发送与人工批准

依赖：里程碑 2、4。

- 在隔离模拟客服窗口完成“客户消息 → 决策 → 回复 → 自动发送”闭环。
- 内置低风险自动发送和高风险人工接管测试用例。
- 只有全部必测用例通过且人工批准后，才生成正式模式批准记录。
- 批准记录包含测试版本、通过时间、操作者和用例摘要；核心配置变化后自动失效。

检查点：不连接真实客服平台也能完整演示自动发送；失败用例无法批准正式模式。

## 里程碑 6：原客服平台自动发送闭环

依赖：里程碑 2、4、5。

- 将低风险回复填入原客服平台输入框并自动点击发送。
- 填入前重新校验账号、客户、最新消息和可见订单。
- 高风险或校验失败时停止任务，由客服在原平台人工接管。
- 记录账号、阶段、耗时、结果和错误码，不记录聊天正文。
- 正式发送适配器强制检查模拟测试和人工批准记录。

检查点：低风险用例可自动发送；高风险用例不会发送；未批准状态无法启动正式模式。

## 里程碑 7：小流量试运行、性能与交付

依赖：里程碑 6。

- 完成稳定性、性能、异常恢复和视觉回归测试。
- 先使用测试账号小流量试运行，再逐步开放正式账号。
- 建立安装包、更新包、本地数据备份和回滚方案。
- 保持既有安装位置、快捷方式和用户资料目录连续。

检查点：通过成功标准并形成试运行报告后，V1 才可交付。

## 关键风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 客服平台 UI 更新 | 元素读取或坐标失效 | 语义选择器优先、局部锚点、版本探测、失败即停止 |
| 多账号切换错位 | 填入错误客户 | 单队列、二次校验、截图证据、零容忍测试 |
| 模型编造 | 错误承诺 | 知识依据必填、敏感规则、缺失事实转人工 |
| 网络或 API 不稳定 | 响应慢 | 超时、重试、熔断、允许客服在平台直接接管 |
| 客户提示注入 | 越权行为 | 客户文本只作为数据、模型无系统工具、代码端执行规则 |
| 隐私泄露 | 合规和信任风险 | 控制台不展示聊天、最小上传、脱敏、凭据保护和保留周期 |

## 并行与顺序关系

- 控制台 UI、知识库编辑器和模拟账号数据可在应用骨架完成后并行。
- 自动化探测必须先于真实模型闭环，否则无法验证账号/客户绑定。
- 风险规则和 JSON 契约必须先于平台输入框填入功能。
- 安装与升级验证在核心功能稳定后进行，但目录和数据路径从里程碑 1 起固定。
